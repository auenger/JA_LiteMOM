# 锦安 WMS 第一期功能范围确认与需求分析

版本：v0.3（需求确认稿）  
日期：2026-09-10  
状态：第一期实现基线（已同步当前实现与部署信息）  
依据：本轮业务说明，以及现有《轻量WMS需求分析与功能拆解-v0.1》《原材料模型与可配置业务规则-v0.2》

> 本文用于记录第一期功能范围、业务规则和当前实现基线。尚不清楚或存在多种实现口径的内容统一列入文末待确认事项，不擅自补充业务规则。

## 1. 第一期建设目标

第一期建设一个具备基本用户权限、基础资料和仓储业务能力的轻量 WMS，包含以下三部分：

1. 系统基础能力：超级管理员、人员信息、页面与操作权限。
2. 原材料仓储：原材料档案、供应商、库存、安全库存预警、一般入库、退料入库和出库。
3. 钢瓶检测仓储：供瓶单位、瓶子规格、五个独立业务状态区、按日期统计入库、待抄码池、抄码记录、良品/不良品调整及良品出库。

第一期的两个核心业务模块为“原材料出入库管理”和“钢瓶检测仓储管理”。

### 1.1 技术与界面实现约束

- 前端采用 Vue 3、TypeScript 和 Vite，后端采用 FastAPI，业务数据库采用 PostgreSQL，通过 Docker Compose 部署。
- 界面参考既有设计稿：黑色顶栏、白色侧栏、冷灰页面、红色主操作、紧凑表格与状态标签；不保留外部品牌内容。
- 系统内业务图标统一使用 Nieobie `game-icon-pack` 的圆润 SVG 图标，并作为本地静态资源随系统发布。
- 页面中不使用 emoji 充当图标，不混用其他业务图标集。

### 1.2 当前部署基线

- 采用 Docker Compose 单机部署，固定 Compose 项目名为 `ailitewms`。
- Nginx 对外提供前端并代理后端 `/api`；具体线上地址保存在私有运维资料中。
- FastAPI 与 PostgreSQL 只在 Docker 内部网络通信，数据库端口不对公网开放。
- 发布版本保存在 `/opt/ailitewms/releases`，`/opt/ailitewms/current` 指向当前版本。
- PostgreSQL 使用 `ailitewms_postgres_data` 持久化卷，更新应用时不得删除该卷。

## 3. 系统管理与权限

### 3.1 超级管理员

- 系统初始化时预设两个超级管理员账号：主账号 `admin` 和备用账号 `admin_backup`。
- 超级管理员默认拥有第一期所有页面访问权限和所有操作权限。
- 超级管理员负责人员维护和权限分配。
- 为避免系统失去管理入口，两个预设超级管理员不得被普通人员删除、停用或取消超级管理员身份，并且不在登录页和人员管理页面展示。
- 首次初始化密码由部署环境变量提供，交付后应立即分别修改；部署文档中记录交付初始账号，系统用户界面不得公开显示。

### 3.2 人员信息

第一期提供最基本的人员信息增删改查。建议最小字段如下：

| 字段 | 说明 |
| --- | --- |
| 人员姓名 | 必填 |
| 登录账号 | 必填且唯一，用于登录系统 |
| 联系电话 | 选填 |
| 备注 | 选填 |
| 启用状态 | 启用/停用；停用后不可登录 |
| 创建时间、修改时间 | 系统记录 |

“部门、岗位、员工编号”等字段本轮尚未明确，可在确认后决定是否进入第一期。

### 3.3 页面与操作权限

第一期权限范围已经明确为页面及页面操作权限，拆为两层：

1. 页面权限：人员能否看到并进入某个菜单或页面。
2. 操作权限：在已授权页面内，能否查询、新增、编辑、删除。

权限可直接分配给人员。超级管理员不受普通权限配置限制。第一期不实现“只能查看本人创建、指定区域或指定供瓶单位”等行级数据范围。

## 4. 基础信息建模

### 4.1 原材料档案

| 字段 | 说明 |
| --- | --- |
| 原材料名称 | 必填 |
| 规格 | 必填或按实际资料维护 |
| 价格 | 原材料的参考价格；具体是采购价还是统一库存参考价待确认 |
| 物料单位 | 原材料实际存储与单据录入的单位，例如瓶、桶、袋 |
| 是否启用单位换算 | 默认不启用，此时只使用物料单位；有换算需求时开启 |
| 库存单位 | 启用换算后用于库存统计展示和安全阈值的单位，例如 kg、L、ml |
| 固定换算比例 | 启用换算后，1 个物料单位对应多少库存单位，必须大于零 |
| 实际物料库存 | 按物料单位累计，由已生效的出入库业务计算，不允许直接修改 |
| 换算库存 | 仅启用换算时显示，等于实际物料库存乘以固定换算比例 |
| 是否启用库存预警 | 启用/不启用，可针对每种原材料独立配置 |
| 安全库存阈值 | 启用预警时填写 |
| 预警状态 | 系统根据当前库存和预警配置计算 |
| 启用状态 | 档案是否允许继续用于新单据 |

建议的预警判定规则：

- 未启用预警：状态为“不预警”。
- 已启用且当前库存高于或等于安全库存阈值：状态为“正常”。
- 已启用且当前库存低于安全库存阈值：状态为“库存不足”。

这里严格按“低于阈值时预警”记录；库存等于阈值时是否也预警，需要业务最终确认。

原材料档案支持 CSV 导入和导出。导出的文件同时作为导入模板；导入时按“名称 + 规格”匹配，已存在档案执行更新，不存在档案执行新增，库存数量不通过档案导入修改。

### 4.2 供应商信息

供应商为原材料业务的基础信息，提供增删改查。建议最小字段为：

- 供应商名称。
- 联系人。
- 联系电话。
- 地址。
- 备注。
- 启用状态。

一般入库单是否必须选择供应商、退料入库是否需要供应商，由单据类型决定并待确认。

### 4.3 供瓶单位

供瓶单位表示本批或本只钢瓶来自哪个单位，提供增删改查。建议最小字段为：

- 单位名称。
- 联系人、联系电话、地址、备注。
- 是否默认。
- 排序序号。
- 启用状态。

在钢瓶录入页面中，启用的供瓶单位按“默认项优先、排序序号升序”展示。系统同一时间原则上只允许一个默认供瓶单位。

### 4.4 瓶子规格

瓶子规格提供增删改查，建议最小字段为：

- 规格名称。
- 对应检测价格。
- 是否默认。
- 排序序号。
- 启用状态。
- 备注。

在钢瓶录入页面中，启用的规格按“默认项优先、排序序号升序”展示。系统同一时间原则上只允许一个默认规格。检测价格在业务发生时建议保存快照，避免以后修改规格价格导致历史业务金额变化。

## 5. 原材料出入库管理

### 5.1 库存原则

- 原材料库存按物料单位维护实际数量，单据数量也使用物料单位。
- 未启用单位换算时只显示实际物料库存，安全阈值使用物料单位口径。
- 启用单位换算后同时展示换算库存，换算公式为“实际物料库存 × 固定换算比例”，安全阈值使用库存单位口径。
- 原材料数量、库存、换算比例、价格、阈值及金额统一保留并展示两位小数；钢瓶只数等整数计数不受此规则影响。
- 一般入库和退料入库增加库存，出库减少库存。
- 所有库存变化必须来源于对应单据，不能直接编辑当前数量。
- 单据明细至少保存原材料、规格快照、数量和价格快照。
- 默认不允许出库后库存小于零。
- 每次库存变化后重新计算该原材料的预警状态。

本轮没有提出原材料的多仓库、多库位要求，因此第一期暂按一个原材料库存口径分析；是否需要区分多个材料仓库需确认。

### 5.2 一般入库单

用途：记录原材料的正常入库。

建议字段：

- 单据编号。
- 入库日期。
- 入库类型：一般入库。
- 供应商。
- 经办人。
- 原材料明细：原材料、规格、数量、价格、金额。
- 备注。
- 创建人、创建时间、修改人、修改时间。

一张入库单可包含一条或多条原材料明细。单据生效后增加对应原材料库存。

### 5.3 出库单

用途：记录原材料被领用或发出的数量。

建议字段：

- 单据编号。
- 出库日期。
- 领用人或经办人。
- 原材料明细：原材料、规格、出库数量、价格。
- 备注。
- 已退数量、可退数量（由关联退料入库单汇总）。
- 创建人、创建时间、修改人、修改时间。

出库单生效后减少库存。可退数量建议按“原出库数量－累计有效退料数量”计算。

### 5.4 退料入库单

用途：原材料出库后未使用完，将剩余材料重新退回库存。

业务规则：

1. 退料入库单必须绑定一张原出库单。
2. 退料明细只能选择原出库单中存在的原材料。
3. 每种原材料的本次退料数量不得超过该出库明细的剩余可退数量；保存草稿及确认入账时均由后端校验，并在确认时锁定原出库单，防止并发超退。
4. 同一张出库单允许一次还是多次退料尚未明确；建议支持多次退料，并按累计数量控制上限。
5. 退料入库生效后增加库存，同时更新原出库单的已退数量和可退数量。
6. 退料必须保留与原出库单及原出库明细的关联，便于追溯。

### 5.5 单据增删改查边界

用户提出相关信息需要增删改查。为保证库存可靠，建议采用以下边界：

- 未生效的草稿：允许新增、查询、修改和删除。
- 已生效并改变库存的单据：允许查询，不允许直接删除或修改影响库存的字段。
- 已生效单据录错：确定通过撤销或作废处理，按原变化恢复库存并保留操作记录。
- 原材料单据分别记录创建人、最后编辑人、审批确认人、撤销/作废人及各自操作时间，经办人作为业务字段单独保留。

如果已生效单据也允许直接删除，会造成库存来源和当前余额无法核对，不建议采用。

## 6. 钢瓶检测仓储管理

### 6.1 五个独立业务状态区

第一期在业务上使用“库”的名称，但其本质是五个业务状态或区域。系统需要将五者作为相互独立的业务逻辑单元处理，分别维护规则、数量和允许的流转方向，而不是建立通用实体仓库后任意互转。

| 仓库 | 用途 | 第一阶段记录粒度 |
| --- | --- | --- |
| 待检测库 | 新到且需要抄码、检测的钢瓶 | 入库先记数量；抄码后形成逐瓶明细 |
| 暂存库 | 本次送达后暂存、不立即进入检测的钢瓶 | 第一期只按数量记录 |
| 报废库 | 本次送达时已归入报废范围的钢瓶 | 第一期只按数量记录 |
| 良品库 | 完成抄码与检测、结果为良品的钢瓶 | 数量 + 由待检测明细转入的逐瓶信息 |
| 不良品库 | 完成抄码与检测、结果为不良品的钢瓶 | 数量 + 由待检测明细转入的逐瓶信息 |

首次入库只进入待检测库、暂存库或报废库。良品库和不良品库禁止直接入库，只能由待检测钢瓶完成抄码和检测后转入。

### 6.2 钢瓶基础信息与逐瓶信息

需要记录瓶子编码时，单瓶最小信息为：

| 字段 | 说明 |
| --- | --- |
| 钢瓶编号 | 抄码时必填；唯一范围待确认 |
| 瓶子规格 | 从规格配置中选择 |
| 来源客户/供瓶单位 | 从供瓶单位中选择 |
| 生产日期 | 日期选择 |
| 当前业务状态区 | 已建立逐瓶档案的钢瓶使用待检测、良品或不良品状态 |
| 检测结果 | 未检测、良品、不良品；是否需要更多状态待确认 |
| 检测价格 | 建议从规格带出并保存当次价格快照 |

第一期暂存库和报废库确定只保存数量，不记录逐瓶编号和档案。待检测钢瓶入库时先计入批次数量；执行抄码工序后，形成包含钢瓶编号、瓶子规格、来源客户/供瓶单位和生产日期的逐瓶明细，并关联原入库记录。

### 6.3 当日批次入库

当天送来的钢瓶需要保存入库业务记录和必要的逐瓶明细。“当日入库总量”由系统按入库日期实时或汇总计算，不另外建立一张人工总量单。

建议分为单据主表、仓库数量明细和钢瓶明细三层：

1. 入库单主表：入库日期、供瓶单位、本批入库总量、经办人、备注。
2. 仓库数量明细：本批进入待检测库、暂存库、报废库等仓库的数量。
3. 钢瓶明细：抄码时逐只保存编号、规格、来源、生产日期、当前业务状态，并关联原入库记录。

基本数量校验建议为：

`本批入库总量 = 本批各入库去向数量之和`

暂存库和报废库只按数量管理。待检测入库数量是本批可抄码数量上限，累计有效抄码明细不得超过该数量。系统分别显示待检测总数、已抄码数和未抄码数；当本批全部抄码完成时，待检测入库数量与有效逐瓶明细数量一致。

一天可以按实际业务录入入库记录。系统将相同入库日期的有效入库记录汇总为当日入库总量；已作废或已撤销的记录不计入。该汇总值只读，不能人工修改。

### 6.4 独立抄码工序与检测流转

抄码确定为独立工序，不只是入库页面中的一个普通字段。第一期主流程如下：

1. 新到钢瓶登记入库批次。
2. 需要检测的钢瓶按数量进入待检测库，状态为待抄码。
3. 对待检测批次执行抄码工序，逐只记录瓶身编号、生产日期、来源客户/供瓶单位和瓶子规格，同时保存操作人和操作时间；累计抄码数不得超过该批次待检测入库数量。
4. 执行检测工序，记录检测结果。
5. 检测结果为良品时，从待检测库转入良品库。
6. 检测结果为不良品时，从待检测库转入不良品库。
7. 转移时同时减少待检测库数量、增加目标库数量，并更新单瓶当前仓库，保证汇总数量和明细数量一致。

系统至少区分“待抄码、已抄码待检测、检测完成”三个工序状态。未完成抄码的钢瓶不能进入检测完成状态；良品和不良品只能由检测工序判定并转入。抄码和检测是否必须由不同人员操作、检测还需要保存哪些业务字段，仍需确认。

### 6.5 钢瓶数据增删改查边界

- 供瓶单位、瓶子规格及未生效的钢瓶入库草稿支持增删改查。
- 钢瓶明细支持查询与必要的资料修正。
- 已经参与抄码、检测或仓库转移的记录，不建议直接删除或随意修改原入库数量。
- 业务录错时建议通过受控撤销或更正记录处理，避免五个仓库数量与逐瓶明细不一致。

## 7. 建议的页面与菜单

| 一级菜单 | 页面 |
| --- | --- |
| 首页 | 库存概览、原材料预警、系统按日期汇总的今日钢瓶入库数量、五区数量 |
| 基础信息 | 原材料、供应商、供瓶单位、瓶子规格 |
| 原材料管理 | 一般入库管理、材料出库管理、退料入库管理三个独立页面，不在页面内部切换类型 |
| 钢瓶管理 | 钢瓶当日入库、待检测库、抄码、检测、暂存库、报废库、良品库、不良品库、钢瓶查询 |
| 系统管理 | 人员信息、权限管理 |

超级管理员可访问全部菜单。其他人员根据分配结果显示菜单，并由后端再次校验新增、查询、编辑、删除权限。

## 8. 核心数据关系

### 8.1 原材料

`供应商 → 一般入库单 → 入库明细 → 原材料库存`

`出库单 → 出库明细 → 退料入库单/明细 → 原材料库存`

原材料库存是单据变化后的结果，出入库单据是库存变化的依据。

### 8.2 钢瓶

`供瓶单位 + 入库记录 → 按入库日期汇总当日入库总量 + 各状态区数量`

`待检测数量 → 待抄码池 → 抄码并建立逐瓶明细 → 默认进入良品库 → 必要时调整为不良品`

瓶子规格负责提供规格选项和对应检测价格；供瓶单位负责标识来源。

## 9. 第一期建议验收场景

1. 系统初始化后，主、备两个预设超级管理员均可以登录并访问全部页面，且不在登录页和人员管理页面公开展示。
2. 超级管理员新增一名人员，只授予原材料查询权限；该人员不能进入钢瓶或权限管理页面，也不能新增、编辑或删除原材料单据。
3. 新建启用预警且阈值为 100 的原材料；库存为 99 时显示库存不足，库存为 100 时按当前建议显示正常。
4. 一般入库 100 单位后库存增加 100；出库 30 后库存减少为 70。
5. 对原出库 30 创建退料入库 10，库存恢复为 80，可退数量为 20；累计退料不得超过 30。
6. 同一天存在多条有效入库记录时，系统按入库日期自动汇总当日入库总量；作废或撤销的记录不参与汇总。
7. 一批钢瓶总量 100，其中待检测 70、暂存 20、报废 10，系统校验三者合计等于 100；不能直接录入良品或不良品数量。
8. 待检测入库数量为 70 时，累计抄码明细不得超过 70；全部抄码完成时应为 70 条，并且钢瓶编号不允许按最终确定的唯一规则重复。
9. 抄码保存瓶身编号、生产日期、来源客户/供瓶单位、瓶子规格、操作人、操作日期和当日序号；完成抄码后默认进入良品库。
10. 良品库与不良品库支持按瓶身编号、日期查询，并允许双向调整单瓶状态。
11. 待抄码池显示当前总余量、最近日期余量、每日人员抄码量和入库单规格余量。
12. 修改瓶子规格的默认检测价格，不改变已经保存的历史钢瓶检测价格。
13. 已生效且已经改变库存的单据只能通过作废或撤销处理，不能通过普通删除造成库存与业务记录不一致。

- 气瓶检测报告、检测项目明细、电子签章和监管报送。

- 历史 Excel 数据正式导入。

## 11. 开发前必须确认的问题

### 11.1 高优先级

1. **编号唯一性**：钢瓶编号是否全系统唯一？同一编号以后再次送检，是复用原档案还是允许重新建立？
2. **暂存后续流转**：暂存数量以后是否可以转为待检测数量？如果可以，转入时是否补录对应的逐瓶抄码资料？
3. **报废数量后续处理**：第一期只记录报废数量后，是否还需要记录报废数量的减少、处置或出库？

### 11.2 中优先级

4. **人员字段**：人员是否需要员工编号、所属部门、岗位、身份证号等信息？
5. **超级管理员（已确认）**：系统预设主、备两个超级管理员；均禁止普通人员停用、删除或取消超级管理员身份，且不在用户界面展示。
6. **原材料价格**：档案中的价格是默认采购价、最近采购价，还是统一参考价？出库单是否也需要价格和金额？
7. **材料库存维度**：原材料是否只有一个仓库，还是也要按仓库/库位分别统计库存？
8. **退料规则**：是否支持一张出库单多次退料？退料时价格是否沿用原出库价格？
9. **预警边界**：库存“等于”安全阈值时是否预警？预警只在首页和列表显示，还是还需要系统消息通知？
10. **默认配置**：供瓶单位和瓶子规格是否各自只允许一个默认项？排序数字相同时如何处理？
11. **工序人员**：抄码和检测是否必须由不同人员操作？
12. **检测信息**：除良品/不良品外，是否需要记录检测日期、检测人员、备注、具体检测项目或待复检状态？
13. **钢瓶日期**：生产日期要求精确到日、月还是只记录年份？

## 12. 移动端快速入库与快捷抄码补充需求

### 12.1 快速入库

- 移动端登录后提供独立的“快速入库”入口，并受页面访问权限控制。
- 入库日期固定为系统当天，供瓶单位默认选择基础配置中的默认项。
- 每个钢瓶规格分别填写待检测、暂存和报废数量，系统汇总本批总量并生成一张有效钢瓶入库单。
- 待检测数量进入待抄码池；暂存、报废第一期仍只记录规格数量，不建立逐瓶档案。

### 12.2 快捷抄码

- 原“快捷入库”更名为“快捷抄码”，抄码时不再逐瓶创建钢瓶入库单。
- 可选择一张有剩余数量的入库单抄码，也可针对待抄码总池操作；总池模式按规格自动占用最早入库批次。
- 待抄码池累计所有有效入库单尚未抄码的待检测数量，支持跨日继续；独立页面展示总量、按原入库日期的每日余量、批次规格余量和每日抄码总量。
- 每个工作日的抄码序号从 1 开始逐瓶递增，钢瓶明细记录抄码日期和当日序号。
- 快捷抄码字段按“瓶身编号、生产日期、检测备注”排列；瓶身编号必填，生产日期和备注选填。
- 编码前缀和检测备注由基础信息中的“抄码快捷配置”维护，点击快捷按钮可写入对应输入框。
- 普通抄码和快捷抄码完成后均默认检测通过并进入良品库，共用当日连续序号；快捷抄码成功后清空编号、生产日期和备注，保留当前来源模式与规格。

### 12.3 良品与不良品库

- 不再保留独立检测工艺页面；良品库、不良品库分别分页展示。
- 可按瓶身编号和日期筛选，并在良品、不良品之间双向调整状态。
- 钢瓶规格的检测价格只在瓶子规格维护页面及后续利润计算页面展示，入库、抄码、检测、库存等其他页面均不展示。

## 13. 分页查询与良品出库补充需求

- 所有表格列表接口默认分页，每页 20 条，并返回 `items、total、page、page_size`；前端表格统一配置分页组件。
- 待抄码池默认查询当天往前共 10 天，可选择日期区间；每日待抄码余量、每日抄码总量、入库单余量明细分别分页。
- 每日抄码总量按抄码日期和人员汇总；抄码记录默认显示当前登录人员当天数据，并支持日期、人员和瓶身编号筛选。
- 原“抄码工序”调整为只读“抄码记录”。
- 新增良品库钢瓶出库单，保存客户、经办人、各规格出库数量和备注；草稿允许修改、删除，审批后从良品库按规格分配钢瓶，撤销后返回良品库。
- 良品出库单记录创建人、修改人、审批人、撤销人及对应时间。

## 14. 当前结论

按照本轮说明，第一期可以确定为：

- 两个预设超级管理员（主账号与备用账号），均拥有全部页面和操作权限。
- 一套人员资料与页面访问、查询、新增、编辑、删除权限管理；不包含行级数据范围。
- 四类基础资料：原材料、供应商、供瓶单位、瓶子规格。
- 一套原材料库存体系：一般入库、退料入库、出库、库存查询和安全预警。
- 一套钢瓶仓储体系：按规格入库、跨日待抄码池、快捷抄码、良品/不良品双向调整、良品出库和分页查询。

文末高优先级问题确认后，即可进一步形成第一期最终需求基线、数据库实体关系、页面原型和接口清单。
