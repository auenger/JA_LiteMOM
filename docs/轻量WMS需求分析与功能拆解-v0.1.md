## 1. 建设目标与范围

建设一套供十几名员工使用的轻量业务系统，解决以下问题：

1. 谁能登录、属于哪个部门、能看哪些数据、能做哪些操作。
2. 每只气瓶是什么规格、属于谁、在哪里、检测和流转状态是什么。
3. 每天收进、发出哪些气瓶，瓶号、类型、数量和费用是否可追溯。
4. 原材料买入、领用、退回和当前库存是否准确。
5. 应收、已收、未收，以及应付、已付、未付是否清楚。
6. 出入库单据能否查询、打印、冲销，并关联操作人。
7. 报废气瓶能否按唯一身份追溯，并阻止继续正常出库。

首期面向单公司使用；支持多个部门和库位。仓库数量可配置，初始可只启用一个仓库。先完成业务闭环，不引入复杂采购审批、总账会计、多公司 SaaS 或设备自动采集。

## 2. 必须区分的业务概念

### 2.1 客户送检气瓶与公司自有气瓶

建议将气瓶流转分成两条业务线，避免将客户的瓶误算成公司可出售库存：

| 业务线 | 所有权 | 典型流程 | 主要收费 |
| --- | --- | --- | --- |
| 客户送检 | 客户所有，公司代管 | 接收入库 → 检测登记 → 合格返还或报废处理 | 检测费、材料费及其他约定费用 |
| 自有气瓶购销 | 公司所有 | 采购入库 → 在库 → 销售出库 | 气瓶销售价，可按约定另列检测费 |

用户已补充：公司自有一般是原材料。因此首期主线为客户送检，自有气瓶购销作为可选功能；换瓶等特殊业务暂不展开。

库存界面分别显示“实物在库数量”“公司自有数量”“客户代管数量”，不直接合并为可销售库存。

### 2.2 收付款不能只用一个已付款字段

| 场景 | 系统应记录 |
| --- | --- |
| 向供应商采购气瓶、原材料 | 应付金额、已付金额、未付金额 |
| 向客户销售气瓶、提供检测服务 | 应收金额、已收金额、未收金额 |
| 部分结算 | 部分收款或付款，多次登记 |

入库不一定产生应付，例如客户送检；出库不一定产生应收，例如原材料内部领用。款项由单据业务类型决定。

## 4. 功能模块拆解

### 4.1 用户、部门、角色和权限

| 功能 | 需求 |
| --- | --- |
| 用户 | 新增、编辑、启停、重置密码、分配部门和角色 |
| 登录 | 账号密码登录、退出、修改密码；关闭公开注册 |
| 部门 | 树形管理、部门负责人、启停 |
| 角色 | 自定义角色，一个用户可分配多个角色 |
| 菜单权限 | 控制可见菜单和页面 |
| 操作权限 | 区分查询、新增、编辑、过账、冲销、收付款、打印、导出、报废确认 |
| 数据权限 | 首期建议全部数据、所属部门、本人创建三个范围；单据及对应查询、打印、导出统一校验 |
| 操作审计 | 记录操作人、时间、业务对象、关键变更内容；不得记录明文密码 |

建议初始角色：系统管理员、仓库人员、检测人员、财务人员、负责人/只读人员。角色权限由配置决定，不在代码中绑定具体姓名。

菜单隐藏仅是界面控制，后端必须再次验证身份、动作权限和数据范围。收付款及敏感价格信息应配置可见权限。

### 4.2 仓库、库位与基础字典

- 仓库：编码、名称、负责人、启停状态。
- 库位：所属仓库、编码、名称、用途（待检、合格、隔离、报废待处置等）。
- 基础字典：计量单位、气瓶类型、介质、单据类型、付款方式、报废原因等。
- 已被业务引用的基础资料允许停用，不允许直接删除破坏历史关联。

### 4.3 气瓶类型与规格配置

| 字段 | 说明 |
| --- | --- |
| 类型编码、名称 | 如实际经营的氧气瓶、氮气瓶等，由公司维护 |
| 规格编码、名称 | 同一类型下区分不同规格 |
| 公称容量、容量单位 | 容量必须带单位，默认使用 L 是否适用待确认 |
| 介质、压力、材质 | 按实际档案需要选填，不预设强制值 |
| 默认采购价、默认销售价 | 作为开单参考，不覆盖历史成交价格 |
| 默认检测费用 | 可带入单据，授权人员可调整 |
| 启停状态、备注 | 停用不影响历史查询 |

规格配置描述“一类瓶”；气瓶档案描述“一只瓶”，两者不能合并。

### 4.4 单瓶档案与唯一编号

- 每只气瓶分配系统内部唯一编码，并支持条码/二维码显示与打印。
- 保存原始瓶号/制造编号、制造单位、气瓶类型、规格、制造日期等档案字段。
- 原始瓶号是否跨厂家唯一需要确认；默认不将原始瓶号单独作为系统唯一主键，支持厂家与瓶号联合检索和重复提示。
- 保存所有权类型、当前所有方、当前仓库/库位、最近检测信息。
- 所有权变化保留历史，不能通过编辑档案悄悄变更。
- 单瓶详情展示接收、检测、发出、退回、报废、处置完整时间线。
- 区分三个维度：实物位置（在库/已发出）、检测状态（待检/合格/不合格）、生命周期状态（正常/报废待处置/已处置）。
- 下次检测日期由有权限人员按业务规则维护，首期不内置未经确认的检测周期算法。

### 4.5 原材料配置

- 字段：物料编码、名称、分类、规格型号、基础单位、默认采购价、安全库存、启停状态、备注。
- 按物料和库位维护数量；数量支持小数，精度按单位和业务约定配置。
- 采购入库、领用出库、退料入库、采购退货、盘点调整均保留流水。
- 检测使用的材料可关联检测记录或送检单，以追溯耗用及费用。
- 依据实际台账，增加颜色、规格、型号及单位精度；公斤/千克统一为kg，包装规格不等于单位。批次、保质期和复杂多单位换算后续按需扩展。

### 4.6 供应商与客户

统一往来单位档案，同一单位可以同时是供应商和客户。

- 字段：单位编码、名称、单位类型、联系人、电话、地址、结算方式、备注、启停状态。
- 可选字段：统一社会信用代码、开票资料、银行账户；仅在业务需要时维护并限制可见范围。
- 客户用于送检接收、检测返还、销售出库等业务。
- 供应商用于气瓶采购、原材料采购和退货业务。
- 单位详情支持查看关联单据、代管气瓶、收付款记录、往来余额。

### 4.7 气瓶入库

首期建议支持客户送检接收、采购入库、销售退回三种类型。

单据主表：单据号、业务类型、业务日期、仓库、往来单位、所属部门、经办人、备注、状态。

单据明细：气瓶内部编码、原始瓶号、类型、规格、容量、库位、单价、费用项目、金额。

处理规则：

1. 支持按编号录入、扫码录入、批量选择；新瓶可在接收时建立档案。
2. 每行关联一只气瓶，数量为 1；界面可按规格汇总显示数量。
3. 相同气瓶不能重复在库，同一单据内不能重复录入。
4. 客户送检需记录所有方，不产生采购应付；采购入库按规则形成应付。
5. 草稿保存不改变库存，确认过账后增加实物在库数量并写流水。
6. 客户气瓶在出库后可以再次送检，创建新的业务周期，不新建重复档案。

### 4.8 检测登记与检测费用

这是气瓶检测公司的最小业务闭环，首期提供轻量登记，不替代专业检测报告系统。

- 关联气瓶和本次送检接收单，记录检测日期、检测人员、结果、检测费用、备注。
- 检测结果建议区分合格、不合格、待复检；是否触发报废由独立流程处理。
- 可关联材料耗用单和收费明细；不能仅修改检测备注就扣除材料库存。
- 不合格气瓶进入隔离/待处理范围，不允许按合格气瓶正常发出。
- 如允许不合格原瓶退回，应设置专门业务类型、审批权限和交接说明。
- 检测费应收节点可配置为接收、检测结算或返还确认，默认建议检测结算确认；每次服务冻结规则版本，各后续单据引用同一结算，不重复记账。

### 4.9 气瓶出库

首期建议支持检测返还、销售出库、采购退货；报废实物移出通过报废处置单完成。

- 选择实际在库气瓶，显示瓶号、规格、容量、所有方、检测状态及出库资格。
- 客户送检返还原则上只能选择该客户本次或指定批次的气瓶。
- 销售出库原则上只能选择公司自有且符合发出条件的气瓶。
- 记录接收客户、交接人、业务日期、经办人和备注。
- 发出费用、单价和金额保留当时快照；默认价格变化不影响历史单据。
- 确认过账时校验并扣减库存、写流水、更新位置状态、生成或关联结算记录。
- 是否允许欠款发货由公司配置；首期建议允许并明确显示欠款，不默认为强制拦截。

### 4.10 原材料出入库

| 类型 | 库存变化 | 款项关系 |
| --- | --- | --- |
| 采购入库 | 增加 | 产生应付 |
| 检测领用/内部领用 | 减少 | 不直接产生客户应收 |
| 退料入库 | 增加 | 关联原领用单 |
| 采购退货 | 减少 | 冲减关联采购应付；已付款部分进入退款处理 |
| 盘点调整 | 按差异增加或减少 | 不自动生成现金收付款 |

主表包含日期、仓库、供应商或领用部门、经办人；明细包含物料、规格、单位、数量、单价、金额、库位。默认禁止负库存。

### 4.11 收付款与往来账

- 收款单：客户、日期、金额、方式、经办人、关联应收单据、备注。
- 付款单：供应商、日期、金额、方式、经办人、关联应付单据、备注。
- 一张业务单据支持分次结算；一笔款可分配至多张同一往来单位、同一方向的结算单。
- 首期不做跨客户分摊、应收应付自动抵销；超出未结金额的录入应阻止，预收预付后续明确后再支持。
- 未收 = 应收净额 − 有效收款分摊净额；未付 = 应付净额 − 有效付款分摊净额。
- 退货、折让和退款必须通过关联记录调整，不直接覆盖“已收/已付”数值。
- 已有结算分摊的业务单冲销时，需同时检查关联款项并走受控撤销/退款流程，不能直接删除。
- 金额使用十进制定点计算；建议单价保留 4 位小数、金额保留 2 位，最终精度和舍入规则待确认。
- 首期只提供业务往来账，不等同于财务总账、利润核算或税务开票。

### 4.12 气瓶报废与处置

按唯一气瓶编码管理，不允许只减少一个汇总数量而丢失具体瓶号。

建议流程：提出报废 → 授权确认 → 标记报废待处置 → 实物处置出库。

- 记录气瓶编码、原始瓶号、客户/所有方、报废原因、判定依据说明、日期、提出人、确认人、处置方式及备注。
- 客户所有的气瓶，记录客户确认情况；是否必须上传授权凭证待确认。
- 报废确认后立即禁止正常销售或返还，但实物仍在仓库时继续计入“报废待处置在库”。
- 实物移出时才减少实物库存，生成处置流水与对应单据。
- 历史气瓶档案和报废记录长期可查；不能通过重新入库或编辑状态绕过报废限制。
- 判错撤销必须走专门授权流程并留痕；已处置气瓶不能通过普通编辑恢复。

### 4.13 库存查询、盘点与日报

- 气瓶库存：按类型、规格、容量、瓶号、客户、所有权、库位、检测状态筛选。
- 原材料库存：按物料、规格、库位筛选，显示数量及低库存提醒。
- 每日出入库明细：业务日期、单据号、方向、业务类型、气瓶类型、编号、数量、往来单位、经办人。
- 单瓶追溯：从当前状态查看所有历史单据和检测、报废事件。
- 盘点：生成盘点记录、登记实盘、显示差异、授权确认调整；保留原因和操作人。
- 盘点期间若库存发生变化，确认前必须校验并提示重新核对，不能使用过期账面数量直接覆盖。
- 原材料库存金额如需展示，必须先确认计价法；未确认前优先展示库存数量及单据成交金额，不宣称准确成本/利润。
- 首期导出 CSV；增加针对现有原材料台账的导入预览、物料映射和异常核对，不做通用 Excel 导入引擎。

### 4.14 单据打印

首期提供气瓶入库单、气瓶出库单、原材料入库单、原材料出库单；报废处置单建议一并提供。

打印内容：

- 公司名称、单据标题、单据编号、业务日期。
- 客户/供应商/部门、仓库、经办人。
- 气瓶编号、类型、规格、容量、数量、单价、检测费及金额（按单据类型显示）。
- 原材料编码、名称、规格、单位、数量、单价、金额。
- 合计数量、合计金额、备注、制单/仓管/交接签字栏。
- 已收/未收或已付/未付可按权限和模板配置显示，注明为打印时结算状态。

首期采用浏览器 A4 打印并支持保存 PDF；自动分页、每页重复表头、明细不被截断。针式多联纸、热敏纸尺寸待提供样张后适配。

草稿打印带“草稿”标识，已冲销单据带“已冲销”标识。已过账单据保存业务字段及价格快照，客户改名或规格改价不改变历史单据内容。

## 5. 通用单据与库存规则

1. 单据状态统一为草稿、已过账、已冲销；复杂多级审批首期不做，关键动作以权限控制。
2. 草稿可编辑或删除；已过账单据不能直接修改数量、价格、往来单位和瓶号。
3. 单据号由服务端生成，建议格式 `业务前缀-日期-流水号`，保证唯一；具体前缀可配置。
4. 库存变更、库存流水、单据状态及相关应收应付必须在同一个数据库事务中完成。
5. 重复点击、请求重试不得造成重复过账；并发出库必须锁定或原子校验库存。
6. 对气瓶同时校验唯一身份、实物位置、所有权、检测结果和生命周期状态。
7. 冲销生成反向流水并保留原记录；若后续已领用、转售、报废或结算，必须先处理依赖，不能无条件回滚历史库存。
8. 库存余额用于快速查询，流水用于追溯和对账，两者必须一致。
9. 操作时间由服务端生成；业务日期可按权限选择，显示和日报按北京时间计算。
10. 首次上线通过“期初气瓶/材料库存、期初应收应付”受控导入或录入，不能伪造采购销售记录来凑余额。

## 6. 建议菜单结构

| 一级菜单 | 二级菜单 |
| --- | --- |
| 工作台 | 首页、今日出入库、待处理事项 |
| 基础资料 | 气瓶类型与规格、气瓶档案、原材料、仓库与库位、往来单位 |
| 气瓶业务 | 气瓶入库、检测登记、检测结算、气瓶出库、报废与处置 |
| 原材料业务 | 材料入库、材料出库 |
| 库存管理 | 气瓶库存、材料库存、库存流水、盘点、期初录入 |
| 往来结算 | 应收、收款、应付、付款、客户/供应商对账 |
| 查询报表 | 每日出入库、检测明细、报废明细 |
| 系统管理 | 公司信息、用户、部门、角色、菜单与权限、字典、计费方案、报废规则、操作日志 |

菜单按角色裁剪。仓管员常用流程控制在少量页面内，不要求日常使用者理解底层配置。

## 7. 核心数据实体建议

| 数据组 | 主要实体 |
| --- | --- |
| 组织权限 | 公司、用户、部门、角色、权限、用户角色、角色权限 |
| 基础资料 | 往来单位、仓库、库位、气瓶类型、气瓶规格、材料档案 |
| 单瓶管理 | 气瓶档案、所有权变更记录、检测记录、报废及处置记录 |
| 出入库 | 单据主表、气瓶明细、材料明细、单据关联关系 |
| 库存 | 单瓶位置、材料库存余额、库存流水、盘点及盘点明细 |
| 结算 | 应收应付、费用明细、收付款单、款项分摊、退款/冲销记录 |
| 审计 | 操作日志、打印记录、过账幂等标识 |

气瓶逐只追踪；材料按数量追踪。基础单据可以共享主表，但两类明细和库存校验分别实现，避免一个万能字段表承载所有逻辑。

## 8. 技术与部署方案

沿用已确定的本地开发、单机云部署路线：

- 前端：Vue 3 + TypeScript + Vite，参考现有页面风格。
- 后端：Python FastAPI，承担认证授权、业务校验、事务和打印数据接口。
- 数据库：PostgreSQL，采用迁移文件管理结构变更。
- 部署：Nginx + FastAPI + PostgreSQL，通过 Docker Compose 管理。
- 服务器：现有阿里云 ECS，Ubuntu 24.04，2 vCPU、2GiB 标称内存、40GB 系统盘、3Mbps 带宽。
- 当前检查：Docker 和 Compose 已安装，暂无业务容器，系统可用内存约 1.1GiB；需要精简进程与连接池。
- 镜像在本地构建为 `linux/amd64`，通过 SSH/SCP 上传导入，降低服务器编译和拉取依赖的压力。
- 数据库使用持久化卷，不开放公网数据库端口；部署更新不删除数据卷。
- 数据每日备份至服务器之外并定期做恢复验证；首期备份目标允许最多约一天数据损失，业务若要求更低需另定方案。
- 前端本地构建，列表分页，按需查询，限制导出规模；首期不引入 Redis、消息队列或 Kubernetes。
- 上线前完成更新、日志轮转、资源限制、镜像获取验证与网络访问配置；HTTPS 和域名上线条件另行落实。

本方案不依赖 Supabase 或 Cloudflare。应用与数据库同机，属于单点部署，不承诺高可用；故障时依靠备份恢复。

## 9. 分阶段实施

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 需求确认 | 确认本稿、实际字段和单据样张 | 确定送检/销售关系、编号规则、收费节点 |
| 基础框架 | 页面布局、登录、用户部门角色权限、基础资料 | 不同角色看到不同菜单，接口权限有效 |
| 核心库存 | 气瓶和材料出入库、库存流水、期初录入 | 真实数据入库出库后数量准确，可追溯 |
| 检测与报废 | 检测登记、客户返还、报废和实物处置 | 待处理气瓶与正常气瓶隔离，所有权不混用 |
| 结算与打印 | 应收应付、分次结算、退货退款关联、单据打印 | 往来金额一致，单据可交接签字 |
| 上线验证 | 多人并发、备份恢复、部署和操作说明 | 十几人典型操作可用，异常场景不破坏账实一致 |

优先打通“客户送检接收 → 检测 → 费用确认 → 返还 → 收款”，以及“材料采购 → 领用 → 库存 → 付款”两条闭环。

## 10. 核心验收场景

1. 仓管员看不到用户管理；直接调用无权限接口也被拒绝。
2. 接收同一客户 10 只气瓶，在库增加 10；再次提交同一单据不重复增加。
3. 两人同时发出同一只气瓶，只有一次成功，并能向另一人说明原因。
4. 返还客户 A 的气瓶时，不能误选客户 B 的气瓶。
5. 气瓶采购、销售、客户送检分别产生正确的所有权和结算结果。
6. 材料库存为 5，并发领用 4 和 3 时不得出现负库存。
7. 应收 500 元，分别收取 200 和 100 元，已收为 300，未收为 200。
8. 检测结算已产生应收，返还出库时不得重复计费。
9. 报废确认后不可正常出库；未实物处置时仍能查到其在库位置。
10. 已过账单据修改被拒绝，冲销保留原单和反向流水，并检查后续依赖。
11. 一张包含多页瓶号的出库单可以完整打印，明细、金额和签字栏可读。
12. 更新应用镜像后库存数据保留；备份可在独立测试环境恢复并核对数量和金额。

## 11. 需公司确认的问题

以下列表保留评审事项；计费方式和报废规则已确定采用后台配置，不再阻塞模型开发。实际经营属性及源表异常在配置初始化或数据导入时核对。

| 优先级 | 问题 | 当前建议/假设 |
| --- | --- | --- |
| 高 | 主要是客户送检，还是同时采购和销售自有瓶？是否存在换瓶？ | 已明确自有库存以材料为主，首期送检优先，自有购销可选；换瓶先不做 |
| 高 | 每只瓶都有可读瓶号吗？不同厂家是否重号？ | 系统唯一编码 + 保留原始瓶号 |
| 高 | 检测费按瓶、规格、客户还是批次计价？何时确认应收？ | 可配置计价方式、匹配条件、应收节点和版本，不写死 |
| 高 | “已付款/未付款”是否同时包含客户收款和供应商付款？ | 双向支持，并支持部分结算 |
| 高 | 报废由谁确认？客户瓶是否必须取得客户授权？如何实物处置？ | 判定条件、确认角色、客户授权要求可配置；确认与实物处置分开 |
| 中 | 实际经营哪些瓶型、容量、材料和单位？是否管理批次和有效期？ | 提供现有 Excel 或纸质台账后确定 |
| 中 | 客户是否允许欠款提瓶？是否需要检测未完成时退回？ | 可欠款，异常退回走专用类型 |
| 中 | 入出库单现有样式、纸张大小、是否显示价格？ | A4，价格按角色及模板控制 |
| 中 | 原材料是否对外销售？检测耗料是否另外向客户收费？ | 默认内部领用，收费另列项目 |
| 中 | 气瓶所有权是否可转移？销售退货是否退检测费？ | 按明确业务规则处理，不能自动全额退款 |
| 中 | 是否需要审批和盘点差异复核？ | 首期关键动作授权，复杂多级审批后置 |
| 中 | 单价是否含税？是否需要库存金额、移动加权成本和利润？ | 首期业务金额，税务与成本核算待确认 |
| 低 | 公司完整地址、电话、Logo、单据签字栏名称是什么？ | 仅保留已提供的名称与地区 |

## 12. 首期不包含的能力

- 法定检测报告自动签发、电子签章、监管平台报送。
- 自动根据制造日期或类型判定法定报废、自动计算法定检测周期。
- 完整会计总账、税务开票、工资和资产管理。
- 多级审批引擎、多公司租户、复杂条码设备集成。
- 离线 PDA、设备实时采集、ERP 自动同步、大批量历史数据清洗。
